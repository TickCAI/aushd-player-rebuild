# 首页信息架构与智能片单方案（v1 讨论稿）

> 目标：把首页从「算法随机堆出来的 34 行」改成「国内用户能预测的分区 + 智能片单」，
> 同时把「我的媒体库」的封面缩到与「继续观看」同一档。
>
> 本文只出方案，不改代码。所有结论都标了依据的文件与行号。

---

## 0. 一句话结论

首页现在的问题不是「缺分类」，而是**没有信息架构**：`lib/ui/pages/home_page.dart:285-340`
一次性生成了 34 个 `_Row`，顺序是「继续观看 → 我的媒体库 → 片单 → 收藏 → 因为你看了X →
最新电影 → 情绪货架 → 最新剧集 → 趋势 → 为你推荐 → 主演 → 标签 → 片单 → …」——
同一类内容（因为你看了X / 主演 / 标签 / 类型）在不同位置重复出现 3–4 次，
用户滚到第 8 行就已经分不清这是「推荐」还是「分类」。

修法不是加更多行，而是**先定 6 个区，再让每个区里只放规则明确的片单**；
「我的媒体库」这一行则从 560×315 缩到 380×214，和继续观看同档。

## 1. 现状：三个可量化的问题

### 1.1 媒体库卡太大（用户指着说的那条）

| 位置 | 数值 | 依据 |
|---|---|---|
| 继续观看卡 | 380×214（16:9） | `lib/ui/theme/tokens.dart:37` `landscapeWidth = 380` |
| 媒体库卡 | **560×315** | `lib/ui/widgets/library_card.dart:19` `libraryCardWidth = 560` |

面积比 560×315 / 380×214 ≈ **2.17 倍**。1920 宽窗口下，继续观看一行放 4.5 张，
媒体库一行只放 3 张还撑满整行——这就是截图里的观感差。

而且卡内还塞了 4 层信息（`library_card.dart:113-148`）：logo 或标题（2 行）+ 类型/数量 +
overview（2 行）+ 模糊底图。缩到 380 时必须砍掉 overview 和大 logo，否则文字溢出。

### 1.2 两张库卡封面完全一样（顺带发现的真 bug）

`lib/data/catalog_api.dart:186-195` 的取图顺序是：

```
backdropImageTags → featuredArtwork（服务端指定的精选条目）→ thumbImageTag → primary
```

`featuredArtwork` 由服务端给，中文 Emby 里「电视剧 / 电影」两个库常被同一套刮削器
指到同一张拼贴图（截图里两张都是「正在热播 HITSERIES」）。**这是数据问题，不是渲染问题**，
但用户看到的观感就是「两张一样的图」，必须处理。

修法：`libraryArtwork` 增加 `excludeTags` 参数，首页按行依次取图并登记已用 tag，
命中重复就跳过下一条候选（fallback 到该库内 `SortBy=Random` 的一个条目 backdrop）。

### 1.3 分类没有逻辑（用户说「太烂」的部分）

`_buildRows` 实际顺序（节选前 12 行）：

| # | 行 | 问题 |
|---|---|---|
| 1 | 继续观看 | ✅ 保留 |
| 2 | 我的媒体库 | 大卡，见 1.1 |
| 3–N | 用户自选片单 | 位置对，但和下面「片单」行重复 |
| N+1 | 我的片单（收藏） | 与 3 语义重叠 |
| N+2 | 因为你看了《X》 | 用种子片推荐，**用户不知道这是分类** |
| N+3 | 最新电影 | ✅ 保留（但要和「本周更新」合并） |
| N+4 | 情绪货架 | 概念太抽象，中文语境下读不懂 |
| N+5 | 最新剧集 | 与 N+3 重复 |
| N+6 | 本周热门 | 只在接了 Seerr 时出现 |
| N+7 | 为你推荐 | 与「因为你看了X」重叠 |
| N+8… | 主演 / 标签 / 类型 / 因为你看了Y | 同样的东西换种子再刷 3 轮 |

**核心矛盾**：这些是「推荐算法」的输出，不是「分类」。国内用户对首页的心智是
**「继续看 / 最近更新 / 榜单 / 分类（剧、影、动漫、纪录、综艺） / 我的片单」**，
而不是「因为你看了《谷雨》」「出演 王千源」。

## 2. 尺寸方案（M1，最小改动）

### 2.1 卡片规格

| 项目 | 现在 | 改成 |
|---|---|---|
| `libraryCardWidth` | 560 | **380**（= `Zs.landscapeWidth`） |
| 高度 | 315 | **214**（380×9/16） |
| 行高（含标题） | `560*9/16+44 = 359` | `214+44 = 258`，与继续观看行同一档 |
| gap | 24 | **22**（`Zs.cardGap`，与其它行统一） |

`home_page.dart:673` 的 `_Kind.libraries => (libraryCardWidth, libraryCardWidth * 9 / 16 + 44)`
改成与 `_Kind.continueWatching` 同一表达式即可。

### 2.2 卡内排版（380 宽时必须砍）

| 元素 | 560 时 | 380 时 |
|---|---|---|
| logo 图 | 高 64 | **去掉**，用文字标题（一行，`Zt.title` 缩到 24 号） |
| 标题 | 2 行 | 1 行 + 省略 |
| 类型 · 数量 | 有 | **保留**（`剧集 · 1,204 部`，`Zt.caption`） |
| overview 2 行 | 有 | **去掉**（挪到详情/悬浮卡） |
| 底图 | 模糊铺底 + `contain` 原图 | 默认 `cover` 填满；仅当 primary 是竖版拼贴（宽高比 < 0.8）才退回 `contain` + `Zc.surface` 纯色底 |

### 2.3 去重

`catalog_api.libraryArtwork(v, {int width, Set<String>? excludeTags})`：

1. 依次尝试 backdrop / featured / thumb / primary；
2. tag 已在 `excludeTags` 里就跳过；
3. 四者都被占，则取该库内一个条目做 backdrop（`SortBy=Random, Limit=1`），并把结果 tag 登记；
4. 首页加载媒体库行时按顺序调用，跨卡去重。

## 3. 信息架构（M2 的核心）

### 3.1 六个区（从上到下，行数从 34 收到 11–12）

| 区 | 行 | 意图 | 依据 |
|---|---|---|---|
| **A 续看区** | 继续观看 | 打开就能接着看 | 现有 `catalog.continueWatching()` |
| **B 更新区** | 本周更新 | 「我这周有什么新的」 | `query(types: Episode/Series, sortBy: DateCreated, 近 7 天)` |
| **C 榜单区** | 热门趋势 / 高分经典 / 新片速递 | 国内用户最熟的三个榜 | 见 §4 规则表 |
| **D 分类区** | 剧集 · 电影 · 动漫 · 纪录片 · 综艺 | 真正的「分类」，替换「我的媒体库」大卡 | `views()` 的 `collectionType` |
| **E 片单区** | 我的片单 / 收藏 | 用户自己攒的东西 | `profiles.list` + `allCollections()` |
| **F 推荐区** | 本周推荐 / 为你推荐（只留 1–2 条） | 算法出口，压到最后 | `TasteProfile` + `recommender` |

顺序理由：A/B 决定「今天要不要打开它」，C 决定「有什么可看」，D 决定「我想看哪一类」，
E/F 是兜底。推荐类全部下沉到 F，因为它们不可预测，放前面会让用户找不到东西。

### 3.2 行的统一形态

- 每行右侧加 `更多 >`（`MediaRow` 已有 title 区，加 trailing 即可），点开进入
  `library_page.dart` 的过滤视图，把该行的 `SmartList` spec 带过去。
- 空行处理：低于 `minItems` 整行隐藏（不显示「暂无内容」）。
- 失败处理：单行异常只隐藏该行 + `debugPrint`，不阻塞其它行（现有行为，保持）。

## 4. 智能片单规则表

八个片单，`kind` 决定数据来源：

| id | 标题 | kind | 查询 / 规则 | 隐藏条件 |
|---|---|---|---|---|
| `this-week` | 本周更新 | emby | `types=[Episode,Series]`, `sortBy=DateCreated`, `descending`, 7 天窗口 | < 4 项 |
| `trending` | 热门趋势 | seerr→hybrid | `seerr.trending(timeWindow:'week')`；库内已有则标「已入库」，否则标「可求片」 | 无 Seerr 且库内无匹配 → 隐藏 |
| `classics` | 高分经典 | emby | `minCommunityRating: 8.0`, 未看优先, `productionYear <= 2015` | < 6 项 |
| `fresh` | 新片速递 | emby | `sortBy=PremiereDate`, 近 90 天, `types=[Movie,Series]` | < 4 项 |
| `gems` | 冷门佳作 | emby | `6.5 <= rating <= 7.8`, `Filters=IsUnplayed` | < 6 项 |
| `one-ep` | 一集入坑 | emby | 每个 Series 取首集（`NextUp` + `Series` 去重） | < 4 项 |
| `picks` | 本周推荐 | hybrid | 口味 genre ∩ `IsUnplayed` ∩ `rating >= 7`，打分排序（§5.2） | < 6 项 |
| `my-list` | 我的片单 | local+emby | `profiles.list` 条目 + 中文名 BoxSet | 空 |

**不做的**：「豆瓣高分」。豆瓣没有公开 API，只能爬，反爬一改就全站空白——
用 `classics`（Emby CommunityRating）+ `gems` 覆盖同一诉求。要真接豆瓣，得单开一个
「外部评分源」抽象，属于另一个里程碑。

## 5. 工程实现

### 5.1 数据模型（新增 `lib/data/smart_list.dart`）

```dart
enum SmartKind { emby, seerr, hybrid, local }

final class SmartList {
  const SmartList({
    required this.id,
    required this.title,          // (L10n) => String
    required this.kind,
    this.types, this.sortBy, this.descending = false,
    this.filters, this.minRating, this.genres, this.years,
    this.window,                  // 时间窗（DateCreated / PremiereDate）
    this.minItems = 4,
    this.limit = 24,
    this.ttl = const Duration(minutes: 30),
    this.priority = 0,
  });
  // …字段见上
}
```

`resolve(services)` 管线：

```
query(Emby)  →  (hybrid) 补 Seerr 可求片并标注来源  →  过滤已看/已入库/重复  →  打分排序  →  缓存
```

### 5.2 打分（仅 `picks` / `gems` / `classics` 用）

```
score = 0.45 * norm(rating)            // CommunityRating / 10
      + 0.30 * tasteMatch              // 命中 TasteProfile.genres / actors / directors 的比例
      + 0.15 * freshness               // 越新越高，半衰期 3 年
      + 0.10 * stableJitter(id)        // 同一批内顺序稳定，不每次刷新都变
```

### 5.3 缓存与请求预算

- 内存 `Map<String, ({List<Object> items, DateTime at})>`，TTL 见 spec；
- 落盘 `smart-cache.json`（`AppLog.directory` 同级），冷启动先读缓存再刷新；
- `services.libraryChanged` 触发整体失效（现有事件，`home_page.dart:115` 已监听）；
- **首屏请求预算 ≤ 3 个**：继续观看 + 第一行 + 媒体库视图；其余行沿用现有
  `_pump()` 的滚动驱动加载（`home_page.dart:157-180`，每次并发 3 行）。

### 5.4 分类区入口

`views()` 已经是 `CollectionFolder` 列表（`catalog_api.dart:111-176`），
按 `collectionType` 映射成中文名（`library_card.typeLabel` 已有映射表）：
`movies → 电影`、`tvshows → 剧集`、`music → 音乐`……未识别的归入「其他」。
点击 = `onOpenLibraryView(view)`（现有回调，`home_page.dart:58`）。

### 5.5 首页布局设置（M4）

`settings_page.dart` 增加「首页布局」子页：每个片的 显隐 / 上下移动，
存 `PlayerSettings.homeLayout`（`List<String> 有序 id + 隐藏集合`）。
默认值 = §3.1 的顺序。**不做的**：拖拽排序（TV 遥控器场景不适合），用「上移/下移」按钮。

| 能力 | 现状 | 影响 |

| 中文片名 | `ContentZh` + `localizer` | 片单标题走 l10n，条目名走现有本地化 |

## 8. 验收清单

1. 媒体库卡与继续观看卡**同宽同高**（380×214），行高 258；
2. 同一首页内**不出现两张相同封面 URL**（打点断言）；
3. 首页总行数 **≤ 12**，行标题**无重复**；
4. 未接 Seerr 时「热门趋势」隐藏，**不出现空白行或错误行**；
5. 首屏 1.5 s 内出前 2 行；首屏请求 ≤ 3 个；
6. 单行失败不影响其它行（现有行为不回归）；
7. `flutter analyze` 0 error + 新增单测全绿 + 云端三平台构建绿。

## 9. 需要你拍板的三件事

1. **要不要接豆瓣？** 我的建议是不接（无官方 API，爬虫一挂首页就空），
   用「Emby 评分 ≥ 8 的高分经典」+「6.5–7.8 的冷门佳作」替代。
2. **Seerr 是常开还是偶尔开？** 决定「热门趋势」是核心行还是可选行。
3. **分类维度优先级**：类型（剧/影/动漫/纪录/综艺）优先，还是地区（国产/美剧/日韩）优先？
   我按「类型优先 + 地区作为第二层筛选」设计，如果反了现在改成本最低。

## 10. 分类浏览页（对标 FlixPilot「流媒体」页，用户 2026-11-19 提出的方向）

用户给的参考（FlixPilot v2.9.1 的「流媒体」页）是成熟做法：**顶部口径 Tab + 多分面筛选条 + 海报网格**。
这跟本文 §3 的「第二层筛选」是同一个东西，只是他把筛选条做成了常驻的一整行。
结论：**可以照这个结构做，而且应该做**——它比首页堆 rows 更适合"我有 3000 部，我想按条件找"。

### 10.1 三段结构

```
[ Tab 行 ]   精选 · 高分榜单 · 最近入库 · 即将上映(可选)
[ Facet 行 ] 平台 / 分类 / 年份 / 类型 / 地区        ← 每行一个维度，可多选
[ Grid ]     200×300 海报，20 列自适应，无限滚动
```

### 10.2 Tab（口径，单选）

| Tab | 定义 | 数据 | 需要 Seerr |
|---|---|---|---|
| 精选 | 混合：继续观看 4 + 本周更新 8 + 高分 8 | Emby | 否 |
| 高分榜单 | `minCommunityRating>=7.5`，按评分降序 | Emby | 否 |
| 最近入库 | `sortBy=DateCreated` 降序 | Emby | 否 |
| 即将上映 | TMDB upcoming，未入库的标「可求片」 | TMDB | **是**（无 Seerr 则整个 Tab 隐藏） |

### 10.3 Facet（分面，多选）

| 维度 | 取值 | 数据来源 | 我方现状 |
|---|---|---|---|
| **平台** | Netflix / HBO / Disney+ / 爱奇艺 / 腾讯 / 优酷 / 哔哩哔哩 / 其他 | Emby `Studios`（+ Seerr `networks`） | ⚠️ `cardFields` 未取 `Studios`，要加 |
| **分类** | 电影 / 剧集 / 动漫 / 纪录片 / 综艺 / 音乐 | `collectionType` + `Genres` 判定（§4 形态表） | ✅ |
| **年份** | 2026…2015 / 更早 | `ProductionYear` | ✅ |
| **类型** | 动作/冒险/喜剧/犯罪/纪录/剧情/家庭/奇幻/历史/恐怖/音乐/悬疑/爱情/科幻/惊悚/战争/西部 | `Genres`（**需中文归一化映射表**：`Sci-Fi`/`Science Fiction` → 科幻） | ✅（缺映射） |
| **地区** | 中国 / 中国香港 / 中国台湾 / 日本 / 韩国 / 美国 / 英国 / 法国 / 德国 / 印度 / 泰国 | Emby `ProductionLocations` | ⚠️ 未取该字段，要加 |

**只显示有数据的口径**：某维度下 0 条目的取值不渲染，避免"点了没结果"。

### 10.4 组合语义（必须先定死，否则筛选会自相矛盾）

- **同维度多选 = OR**（平台选 Netflix + HBO → 两者都算）
- **跨维度 = AND**（平台=Netflix 且 年份=2025 且 类型=科幻）
- 「全部」= 该维度不限制（不是"包含全部"）
- 空结果页要给"放宽条件"的出口（清空最近的一个 facet）

### 10.5 卡片与角标

| 角标 | 取值 | 来源 |
|---|---|---|
| 左上 | 电影 / 剧集（+ 动漫/纪录 时显示细分） | type + genre 判定 |
| 右上 | ★ 8.4 评分 | `communityRating`（一位小数） |
| 右下 | ✓ 已入库 / 可求片 / 看到 E03 | 库内匹配 + `playbackPositionTicks` |

### 10.6 与首页的关系

- 首页保留 rows（继续观看 + 智能片单），这是"不知道该看什么"的入口；
- 浏览页是"我已经知道要看什么"的入口（按条件找）；
- 首页每行右侧「更多 >」跳进浏览页，并把该行的条件**预选**成 facet（例如从"高分经典"进去时 年份=更早、类型=不限、排序=评分）。

### 10.7 落地改造点

| 方案 | 说明 | 取舍 |
|---|---|---|
| A. 扩展 `lib/ui/pages/library_page.dart` | 它已有 sort/genre/watched 三个筛选和库 chips（`:386-440`），加 Tab + 平台/年份/地区 facet 即可 | **推荐**，复用现有分页与网格 |
| B. 新建 `BrowsePage` | 干净，但要复制网格/加载/空态逻辑 | 不推荐，重复代码 |

### 10.8 数据缺口（必须先补，否则 facet 是空的）

1. `cardFields`（`catalog_api.dart:90-92`）加 `Studios,ProductionLocations`；
2. `EmbyItem` 加 `productionLocations`（`List<String>`）字段与解析；
3. 写 `GenreZh` 归一化映射（`Animation/动画/アニメ` → 动漫；`Sci-Fi/Science Fiction` → 科幻），
   放在 `lib/l10n/content_zh.dart` 同侧；
4. 验证 Emby `/Items` 是否支持 `Studios`、`ProductionLocations` 作为筛选参数；
   不支持则客户端过滤（先取 300 条再筛，可接受）。

### 10.9 里程碑调整

| 阶段 | 原计划 | 调整后 |
