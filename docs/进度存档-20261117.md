## 4. soak 的判据（已按第一次的教训重写）

判据必须是**任何环境都成立、且能抓住已知缺陷**的，不能拿插件状态当第二权威：

1. `zerk/window.isFullScreen()` 与**实际几何**自洽（声称全屏 → rect == 全屏 rect；声称窗口化 → rect == 基线）；
2. 全屏 rect **逐轮完全相同**（抓 `SWP_FRAMECHANGED` 缺失导致的"首次进全屏客户区不对"）；
3. 退出后窗口化 rect **与基线精确相等**（抓 placement 累积漂移 / 全屏泄漏）；
4. 每 10 轮并发 `toggleFullScreen()` ×3 不崩不卡，且 state 与几何仍自洽（抓 single-flight 缺失）；
5. 结束 `isFullScreen() == false`；
6. `frames >= 轮次` 且 `p99 < 50 ms`（worst 只记录不设闸，因为 WARP 上它是环境）；
7. 退出码 0（`0` 全过 / `1` 断言失败 / `2` soak 自身异常 / `3` watchdog 240 s）。

harness 会先把窗口 `setSize(640×480)` 压到屏幕内，再断言"全屏覆盖窗口化"——否则在 1024×768 的 runner 上，
默认窗口请求 1600×900 会被夹到 1044×788（比屏幕还大），这个不变式根本不成立（第一次就是这么红的）。
