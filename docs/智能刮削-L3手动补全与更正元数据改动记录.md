# 智能刮削 L3：手动补全媒体库 · 清除缓存 · 更正元数据

本阶段在 L1（文件名解析 / 匹配打分 / 本地缓存）与 L2（可见性预取）之上，补上三个「用户可主动使用」的入口。三条入口全部遵守同一套规则：**零写回上游、只写本地缓存、低置信不自动应用**。

## 一、为什么需要 L3

L2 的预取只覆盖「用户滑到的位置」：海报会在滚动过程中被悄悄补好，但有两类情况它覆盖不到。

1. **刚导入整库的用户**：第一次打开时首页只有几十个条目可见，剩下的要么等用户滑到，要么一直没有封面。
2. **匹配错了的用户**：L2 的设计是「宁缺毋滥」——低于自动阈值（0.78）的一律留空。可留空意味着用户只能看到光秃秃的文件名，而他其实知道那部片叫什么，却没有地方告诉软件。

L3 就是补这两块：一个「补全媒体库」按钮、一个「清除刮削缓存」按钮，以及详情页的「更正元数据」。

## 二、补全媒体库

`lib/data/scraper/library_scraper.dart`（新增，166 行）

- `LibraryScraper.run()` 一次性走完 `Movie` + `Series`，按每页 200 条分页拉取，上限 5000 条。超过上限的部分留给 L2 的可见性预取——一次按钮点击不该让界面转几个小时。
- 只处理 `SmartScraper.needsScrape(item)` 为真的条目：没有 provider id（tmdbId）、没有服务器海报、也没被本地补过。
- 进度通过 `ValueNotifier<LibraryScrapeProgress>` 对外暴露，`LibraryScrapeProgress` 是不可变快照，含 `total / done / applied / failed / running / finished / cancelled`，并提供 `fraction`（`total == 0` 时返回 0，避免除零；`done` 超出 `total` 时 clamp 到 1）。
- **防重入**：`run()` 先判 `running`，正在跑就直接返回当前快照。双击遥控器不会开出两条扫描。
- **可中止**：每个条目之间检查 `_cancel`，`cancel()` 立即生效，已完成的计数保留。
- 单条失败只记 `failed` 并 `debugPrint`，不中断整轮。

设置页 `lib/ui/pages/settings_page.dart` 新增私有组件 `_LibraryScrapeRow`：

- 只在 `services.libraryScraper != null` 时渲染（没有 TMDB key 时整行不出现，不占位置）。
- 用 `ValueListenableBuilder` 直接监听 scraper 的 progress，只有这一行重建，不惊动整个设置页。
- 副标题按状态切换：未开始显示说明、运行中显示「正在扫描 12 / 340…」、完成显示「已完成——补全 87 / 340 部」、取消显示「已停止，120 / 340」、无事可做显示「所有影片都已有封面和简介」。
- 运行中标题变「停止扫描」且图标变 stop，点一下即取消。

`AppServices.libraryScraper` getter 按 `identical(cached.scraper, s)` 判断是否需要重建。TMDB key 或语言一改，`SmartScraper` 就是新实例，旧的进度条必须作废，否则进度会描述上一套配置的扫描。

## 三、清除刮削缓存

设置页 Metadata 段新增一行「清除刮削缓存」，同时清 `SmartScraper.clearCache()`（`scraper_cache.json`，含自动命中与用户手动指定的决定）和 `MetadataLocalizer.clearCache()`（`tmdb_cache.json`），然后 `markLibraryChanged()` 让首页重取。

这条行的副标题明确写了「忘记之前所有匹配结果。你的媒体库不会被修改。」——刮削器的产出始终只是本地渲染层覆盖，清缓存即完全撤销。

## 四、更正元数据

`SmartScraper` 新增两个方法：

- `candidates(EmbyItem, {limit = 5})`：重新查一次 TMDB，把候选按分数降序返回。复用与自动流程完全相同的「文件名解析 → 搜索 → 打分」管线，因此面板里看到的分和自动应用时的分是同一套。任何异常都返回空列表，让界面说「没有找到匹配」而不是抛错。
- `applyCandidate(item, choice)`：把用户选中的候选写进缓存，标记 `verdict: 'user'`、`apply: true`。这样后续 cache 命中会直接沿用，不用每次重新打分——也不会因为原始文件名太差而在下次被重新判成 review。

详情页 `lib/ui/pages/details_page.dart` 在操作行里加了「更正元数据」按钮（`Icons.edit_note_rounded`），只在配置了 scraper 且当前是 Movie/Series 时出现。点击后：

1. 拉候选（带并发闸 `_Gate(3)`，不会因为用户连点而打爆 TMDB）。
2. 弹出侧滑面板，每项显示海报缩略图、`标题 (年份)`、副标题 `87% · auto` 这样的匹配分与判定。
3. 选中后应用，`setState` 更新当前页的 `_item`，`markLibraryChanged()` 让列表同步。

## 五、文案

`lib/l10n/app_en.arb` / `app_zh.arb` 各加 14 个 key，两侧完全对齐（842 个 key，`en-only = 0`，`zh-only = 0`）：

`scrapeLibrary`、`scrapeLibraryHint`、`scrapeLibraryRunning`、`scrapeLibraryDone`、`scrapeLibraryCancelled`、`scrapeLibraryNothing`、`scrapeLibraryStop`、`clearScraperCache`、`clearScraperCacheHint`、`scraperCacheCleared`、`correctMetadata`、`correctMetadataPick`、`correctMetadataApplied`、`nothingFound`。

四个带参数的 key（`scrapeLibraryRunning` / `Done` / `Cancelled`）在 app_en.arb 里带 `@placeholders` 声明。其余五种语言（de/es/fr/pl/ro）没有补这批 key——缺 key 不报错，`app_en.arb` 是 template，缺的会回落英文。

## 六、测试

`test/library_scraper_test.dart`（新增，147 行，9 个用例）：

- `LibraryScrapeProgress`：初始 `fraction` 为 0；`5/10` → 0.5；`10/10` → 1；`9/4` 被 clamp 到 1；`copyWith` 只改指定字段。
- `LibraryScraper` 门控：没有 TMDB key 时 `run()` 返回且**完全不查 catalog**（用 `_ForbiddenClient` 兜底，任何网络调用都会让测试失败）；scraper 为 null 时同样是 no-op；预置 `running: true` 后二次 `run()` 立即返回且 `done/total` 保持原值。
- `needsScrape`：有服务器海报 false、已应用本地海报 false、裸文件条目 true。

## 七、边界说明

- 云端 CI 不连真实 TMDB，只验证编译、单测与构建。真机需要配好 TMDB key 才能看到补全效果。
- 扫描上限 5000 条，超大库（>5000 部待刮）一次点不完，剩余部分靠滚动预取。
- Seerr 之外没有别的元数据源，TMDB 搜不到就仍然留空——这是刻意的，猜错封面比没有封面更糟。
- 用户手选的候选会一直生效，直到清缓存。想重新自动判断就点「清除刮削缓存」。
