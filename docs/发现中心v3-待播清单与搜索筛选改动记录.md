# 发现中心 v3：待播清单、库核对、搜索与筛选

## 0. 结论

在 v2「真实抓取 + 无限下拉」的基础上，按用户反馈做了四点改进：发现卡片从“求片/请求”改为“待播”语义；按 TMDB ID 核对用户已导入的库，命中即跳播放，未命中可加入本地待播清单；修复标题与分类标签（chip）的布局重叠（原为写死的 top padding）；新增搜索与四维筛选（类型 / 排序 / 年份 / 流派）。全部改动在云端 CI（analyze + 单测 + 三平台构建）验证通过。

## 1. 需求 → 对策

| 反馈 | 根因 | 对策 |
| --- | --- | --- |
| 卡片不该是“求片”，应是“待播” | 发现卡片直接复用 `RequestPosterCard` 的 Seerr 请求状态 pill（请求/已请求/下载中） | 给 `RequestPosterCard` 加可选状态覆盖（`statusLabel/statusIcon/statusColor`），发现页传“待播/已在待播/播放”；默认行为不变 |
| 库里有该资源应跳播放界面 | 发现结果始终是 `SeerrMedia`，从不核对本地库 | 用 `Recommender.resolve()` 按 `tmdb.<id>` 批量查库，命中换成 `EmbyItem`；点击命中项 `playItem()` 直接播放 |
| 库里没有应归入待播，不要下载/请求 | 原点击走 `openRequest()` 进 Seerr 请求流程 | 未命中项点击 `profiles.toggle(m)` 加入/移出本地待播清单（zk-profile hub），不走 Seerr |
| 顶部标题与分类标签重叠 | 标题行写死 `top: 64`，与 chip 行 padding 冲突 | 标题行改 `top:28/bottom:6`，搜索/筛选行、chip 行顺序排布，GridView `top:8`，去掉写死偏移 |
| 需要搜索与筛选 | v2 只有 7 个固定分类 chip | 加搜索框（TMDB/Seerr 真搜）+ 类型/排序/年份/流派四个循环 chip，筛选和查询变化触发全新 feed |

## 2. 待播语义（三态卡片）

发现卡片底部 pill 由 `statusLabel/statusIcon/statusColor` 覆盖，呈现三态：

| 状态 | 判定 | pill 文案 | 图标 | 颜色 |
| --- | --- | --- | --- | --- |
| 库内命中（可播放） | `_owned[m.key] != null` | `discoveryPlay`（播放） | play_arrow | success |
| 已在待播清单 | `profiles.inList(m)` | `discoveryInWatchlist`（已在待播） | check_circle | textMuted |
| 未拥有 | 其它 | `discoveryWatchLater`（待播） | bookmark_border | request |

库核对是一次批量查询：`_checkLibrary()` 调 `s.recommender.resolve(_feed.items)`，`resolve()` 按 `tmdb.<id>` 查 `catalog.query(anyProviderIdEquals: ...)`，命中项与输入 1:1 对齐（保持顺序），按索引写回 `_owned[items[i].key]`。

## 3. 搜索与筛选

- 筛选模型 `DiscoveryFilters`（数据层，无 Flutter 依赖，可测）：`mediaType`（all/movie/tv）、`sort`（hot/rating/latest）、`yearFrom/yearTo`、`genre`（TMDB genre id）。`signature` 作为 feed 缓存键的一部分，筛选变化即换新 feed，避免混入旧条件下的分页结果。
- 服务端筛选（`_filteredDiscover`）：类型决定 movie/tv；年份映射 `release_date.gte/lte`（电影）或 `first_air_date.gte/lte`（剧集）；流派 `with_genres`；排序 popularity.desc / vote_average.desc / 年份.desc，评分排序附 `vote_count.gte=100`。
- 搜索（`search(query)`）：TMDB `searchMulti` 或 Seerr `search`，结果再走 `_applyFilters` 客户端过滤（类型/流派/年份），因为 Seerr fallback 无法服务端表达这些维度。
- UI：搜索框 + 5 个循环 chip（类型/排序/年份/流派/清除），切换即 `_resetFeed()`（移除当前 feed、jumpTo(0)、重新加载）。

## 5. 诚实边界

- 云端 CI 不接入真实 TMDB/Seerr：验证的是编译、单测与构建，真实内容需用户在真机配置 key 后确认。
- 待播清单依赖 zerk-profile hub 的 `features.profiles`；未配置 hub 时点击会提示“待播清单不可用”，不静默失败。
- Seerr fallback 的流派/年份筛选为客户端过滤，精度取决于 Seerr 返回的元数据完整度；TMDB 路径为服务端筛选，更准确。
- 库核对按 TMDB id 匹配；若用户的库条目未写入 `tmdb.<id>` provider id（部分 Jellyfin 配置），则无法命中，会归入待播。
