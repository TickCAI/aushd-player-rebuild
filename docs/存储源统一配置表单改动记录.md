# 存储源统一配置表单改动记录

## 背景

真机截图反馈：添加 OpenList / WebDAV / FTP 存储源时，原来是一步步弹出的输入框
（显示名称 → 地址 → 用户名 → 密码），没有协议下拉、端口字段，且用户看不到完整配置全貌。
用户明确要求：**统一配置表单** —— 选完后端后一个面板里填齐 协议 / 主机 / 端口 / 用户名 / 密码，
端口自动并入地址。

## 改动内容（分支 feat/storage-unified-form）

### 1. 新增纯函数工具 `lib/data/mount/mount_url.dart`
- `parseMountUrl(String) → (protocol, host, port, path)`：把已存的 `baseUrl` 拆回表单字段，
  供编辑已有存储源时回填；裸主机名（如 `list.example.com`）默认按 `http` 解析。
- `buildMountUrl({protocol, host, port, path}) → String`：把表单字段拼成 `baseUrl`，
  端口自动并入 authority（`https://host:port/path`）；容忍用户把整段 URL 粘进"主机"输入框。
- `defaultPortFor(protocol)`：协议默认端口候选（http 80 / https 443 / ftp 21）。
- 无 Flutter/UI 依赖，可在 CI host 上直接单测。

### 2. 新增统一表单弹窗 `lib/ui/widgets/storage_form_dialog.dart`
- `showStorageFormDialog(...)` → `Future<StorageFormResult?>`（取消返回 null）。
- 一个面板内依次展示：显示名称、**协议下拉**（HTTP / HTTPS / FTP，用 `SettingChoiceRow`）、
  主机地址、端口、可选路径、用户名、密码（密文）。
- 保存时调用 `buildMountUrl` 合成地址，调用方仍只持有一个 `baseUrl` 字段，数据模型不变。

### 3. `lib/ui/pages/storage_sources_page.dart`
- `_editFlow` 从"四次 showTextInputDialog 串联"改为"一次 showStorageFormDialog"。
- OpenList 仍自动用用户名/密码换取 bearer token（失败则留空，可浏览公开实例）。
- 协议/网盘下拉（`ProtocolPreset.all`）保持不变，选完后端后进入统一表单。

### 4. l10n（app_en.arb / app_zh.arb 同步新增）
新键：`storageProtocol` / `storageProtocolHttp` / `storageProtocolHttps` / `storageProtocolFtp` /
`storageHost` / `storageHostHint` / `storagePort` / `storagePortHint` / `storagePath` /
`storagePathHint` / `storageFormHint`。

### 5. 单测 `test/mount_vfs_test.dart`
新增 `mount URL helpers` 分组 3 用例：字段合并、拆包回填、build/parse 往返稳定。

## 验证

- 两个 arb 文件 `ConvertFrom-Json` 通过（en 57257B / zh 43936B，UTF-8）。
- 云端 CI build.yml（Validate + analyze/test gate + Build windows/linux/androidtv + Publish）。

## 诚实边界

- 协议下拉提供 HTTP / HTTPS / FTP 三种；端口默认留空（用协议默认端口），
  用户可手填覆盖。WebDAV 通常用 HTTPS，选 HTTPS 即可。
- 统一表单不新增数据字段：`MountDefinition` 仍存单个 `baseUrl`（含端口），
  编辑时由 `parseMountUrl` 拆回展示，无 migration 成本。
- 后端为 OpenList 时，端口填在"端口"栏会自动并入地址，
  例如 `https` + `list.example.com` + `5246` → `https://list.example.com:5246`。
