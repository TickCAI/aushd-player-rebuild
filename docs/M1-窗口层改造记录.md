# M1 落地记录：窗口层改造（2026-11-18）

> 对应 `docs/全屏崩溃-解决方案v1.md` §3.2 / §3.3 / §5 的 M1。
> 分支 `ci/m1`，验证手段：GitHub 云端（windows-latest）+ `--window-soak` 夹具，**全程未在开发机实测**。

## 0. 一句话结论

窗口层从「两个权威各说各话 + 每次 WM_SIZE 都同步搬窗口」改成「**原生是唯一权威，Dart 只排队和校验**；resize 合并到 80ms 定时器、只移动尺寸真的变了的窗口」。
云端 40 轮 soak 全绿：`style` 逐位往返、全屏几何 == 显示器 rect、`wmSize=131 / transitions=88`（每轮 1.5 次 WM_SIZE）、`mismatch=0`、`setWindowPosFailures=0`。

## 1. 改了什么

### 1.1 C++（`windows/runner/`）

| 文件 | 改动 | 为什么 |
| --- | --- | --- |
| `window_metrics.h`（新增） | 六个进程级计数器 | 没有计数器就只能靠人肉读日志判断"是不是又递归 resize 了" |
| `native_window.h/.cpp` | `SetFullScreen` 由 `void` 改 `bool`；`GetMonitorInfo` 失败**返回 false 且不改状态** | 原来失败也 `result->Success()`，Dart 以为成功、原生没动、mpv 的 `user-data` 又是第三份状态 |
| 同上 | 进全屏补回 `SWP_FRAMECHANGED` | 1.0.9 删掉它是基于对 dump 的误读（把栈上的返回地址当成 faulting PC），删掉后客户区要等下一次任意 resize 才正确 |
| 同上 | 出全屏恢复 `saved_style_` + `saved_placement_`，`saved_maximized_` 为真则 `ShowWindow(SW_MAXIMIZE)` | 只还原 style 会丢掉"退出全屏时的最大化语义" |
| 同上 | 新增 `diag`（style / windowRect / clientRect / monitorRect / 六个计数器） | soak 的断言需要看原生内部状态，不能只看 `isFullScreen()` |
| `video_host.h/.cpp` | `OnParentResized()` 不再直接 `MoveWindow`，改成 `SetTimer(80ms)`；新增 `FlushResize()` 做真正的移动 | 一次全屏切换会来 3–4 个 `WM_SIZE`，原来每个都同步 `MoveWindow(..., TRUE)` 直接重绘 → mpv 侧 swapchain 连续重建 |
| 同上 | `FlushResize()` 里**先比较尺寸**，相同就不动；`GW_CHILD` 加 `IsWindow`；`MoveWindow(..., FALSE)` | 移除帧同步重绘；mpv 的 VO 子窗口可能还没创建/正在销毁 |
| 同上 | `Hide()` / `~VideoHost()` 补 `IsWindow`、`KillTimer`、清 `GWLP_USERDATA` | 原来析构只 `DestroyWindow`，定时器还在跑就会打到已释放对象 |
| `win32_window.cpp` | `WM_SIZE` 判 `SIZE_MINIMIZED`；`GetClientRect` 用参数 `hwnd`；零尺寸跳过 | 最小化时客户区是 0×0，原来照样 `MoveWindow` → 驱动最容易被 0 尺寸状态打空 |
| 同上 | `WM_DPICHANGED` 的 `SetWindowPos` 加 `SWP_NOSENDCHANGING` | 200% DPI 下 DPI 变化 → resize → 又触发 DPI 变化，无闸门 |
| 同上 | `Destroy()` 加 `destroyed_` 幂等；`DefWindowProc` 用参数 `hwnd` | `WM_DESTROY` → `Destroy()` → `OnDestroy()`，析构再 `Destroy()` → **OnDestroy 至少两次**，`g_active_window_count` 可能减两次、提前注销窗口类 |
| `flutter_window.h/.cpp` | `SetNextFrameCallback` 改 `[this]` + `detached_` 守卫；`WM_FONTCHANGE` 加空判 | 回调被引擎持有，首帧前销毁即悬垂；`ReloadSystemFonts()` 在引擎已销毁后调用就是一步到 AV |

### 1.2 Dart（`lib/`）

| 文件 | 改动 | 为什么 |
| --- | --- | --- |
| `core/windows/native_window.dart` | `setFullScreen` → `Future<bool>`；新增 `WindowDiag` + `diag()`；**删除 `toggleFullScreen()`** | 返回值必须能表达"原生真的做了"；toggle 那种"先读再写"的两跳在并发下必然打架 |
| `core/windows/fullscreen_controller.dart`（新增） | 串行队列 + `FullscreenPhase` FSM + 3s 超时 + 落地后回读原生状态定权威 + 不一致记 `failures` 并写日志 | 全屏只能有一个权威；三个入口（F11、启动、OSD）现在排同一队列 |
| `main.dart` | 启动时 `await FullscreenController.instance.sync()`；启动全屏与 F11 全走 controller | 启动全屏原来发生在首帧回调之前，且与 `window_manager` 的尺寸设置交叉 |
| `playback/mpv/mpv_backend.dart` | OSD 的 `_toggleFullscreen()` 走 controller，`user-data/zerk/fullscreen` 用 controller 的结论 | 去掉"mpv 以为自己是全屏、窗口其实不是"的第三份状态 |
| `window_soak.dart` | 全部切换走 controller；新增 **style 逐位往返**、**全屏 == 显示器 rect**、**`mismatch==0`**、**`wmSize <= transitions*6+6`** 四条断言 | 原来的断言只看 `isFullScreen()` 和 bounds，抓不到 style 残留和 resize 递归 |

`d4a3847` 的 soak 报告（40 轮，无 libmpv）：

```
baseline windowed bounds=960x540 style=0x14cf0000 window=960x540
fullscreen rect=1024x768 style=0x14000000
i=5..40 ok bounds=960x540
concurrent-toggle settled=windowed   (×4)
window layer: wmSize=131 transitions=88 moves=0 coalesced=0 minimizedResize=0 mismatch=0
monitor rect=1024x768
frames=1479 worst=59ms p99=34ms
transition frame budget=58ms (4x idle median 14ms, floor 50ms)
PASS iterations=40 frames=1518
```

读法：

- `style 0x14cf0000 → 0x14000000 → 0x14cf0000`：`WS_CAPTION|WS_THICKFRAME|WS_SYSMENU|WS_MINIMIZEBOX|WS_MAXIMIZEBOX`（`0x00cf0000`）全清且**逐位还原**，40 轮无残留。
- `fullscreen 1024x768 == monitor 1024x768`：客户区真的填满了显示器，不是"以为填满"。
- `wmSize=131 / transitions=88`：一次切换约 1.5 次 `WM_SIZE`，且 40 轮内没有递归放大。
- `worst=59ms`（改造前同 harness 首轮 362ms、200 轮验收 222ms）：跨 run 有环境噪声，不作为定理，但方向一致——同步 `MoveWindow(TRUE)` 链被拆掉后过渡期停顿时长明显下降。

## 3. 云端**没有**证明的东西（必须诚实列出）

1. **`moves=0` / `coalesced=0`**：soak 模式不创建 video host（云端也故意不装 libmpv），所以"合并 `WM_SIZE`、只移动尺寸不同的窗口、`IsWindow` 守护 mpv 子窗口"这条最关键的路径**一行都没跑到**。它只能靠有 libmpv 的真机（L3）验证。
2. **托管 runner 没有 AMD GPU**：`amdxx64` 那次崩溃云端永远不会复现。soak 绿只说明"窗口层没有回归、几何与 style 不变量成立"，**不等于**崩溃已修。
3. `minimizedResize=0`：soak 不会最小化窗口，`SIZE_MINIMIZED` 分支同理未覆盖。
4. 200 轮长跑（`soak-long`）是另一条 job，结果见 run 记录。

## 4. 下一步

- M2：mpv 生命周期 quiesce（`stop` → 等 `vo-configured=false` → 等 ≥2 帧 → `hide` → 等 100–200ms → `command('quit')` + 等 `MPV_EVENT_SHUTDOWN` → `terminateDestroy` → 关 events），把 `MpvBackend.close()` 与 `_finish()` 的 `unawaited` 链路改成有序。
- M2 之后才有资格谈 L3：真机 30 分钟 / 200 次切换 + 播放 4K HDR 的全流程。
