# 发现中心 v4：详情页跳转、筛选面板、流媒体平台、首页改发现抓取

## 0. 结论

按用户 5 点反馈一次改完：发现卡片点击不再直接播放，改为进详情页（库命中→Emby 详情，未命中→Seerr 详情），播放只在详情页里由用户点播放/选集触发；四个"点击循环"的筛选 chip 换成一个筛选触发按钮 + 侧滑详细列表面板（类型/排序/年份/地区/影片分类）；修掉下滑时筛选栏与海报的叠加错误；媒体库的"出品方"facet 改成"流媒体"（只列爱奇艺/腾讯/优酷/芒果/哔哩/奈飞/迪士尼/HBO/Prime/Apple/BBC 等主流平台）；首页的热门趋势/热门剧集/本周推荐/为你推荐四行不再切本地库，改为真实发现抓取并做库匹配。全部走 GitHub 云端 CI 验证（本机无 flutter/dart）。

## 1. 五点反馈 → 实现

| 反馈 | 实现 |
| --- | --- |
| 点击不该直接播放，应进详情页再播放/选集 | `discover_page._openCard`：库命中→`openItem`（Emby 详情，内含播放按钮）；未命中→`openRequest`（Seerr 详情，内含播放/请求）。删除原 `playItem` 直接播放与 `openRequest` 之外的待播 toggle |
| 筛选要详细列表分类，不要点击循环 | 新增 `lib/ui/widgets/discovery_filter_panel.dart`：一个侧滑面板，分区列出 类型/排序/年份/地区/影片分类；页面顶部只留一个筛选触发 chip，点开面板，选完"应用"。`DiscoveryFilters` 加 `region` 维度、`genreOptions` 扩到 19 类、新增 `regionOptions`（12 项） |
| 下滑时筛选栏与海报叠加 | GridView 由 `Clip.none` 改 `Clip.hardEdge`；顶部标题/搜索/分类块包进带不透明 `Zc.background` 的 Container。焦点放大(1.06×)与滚出的卡片不再画到 header 上 |
| "出品方"应是"流媒体" | `library_page`：facet 文案 出品方→流媒体；选项从"库里所有 studios 平铺"改为固定主流平台白名单 `_streamingPlatforms`，按标题 studio 名的子串模糊匹配（爱奇艺/netflix/奈飞…）；只列库里真实存在的平台。服务端不再传精确 Studios（平台 key 非真实 studio 名会查空），改本地过滤 |
| 首页四行改发现抓取 | `home_page._discoveryRow`：热门趋势=trending(week)、热门剧集=popularShows、本周推荐=todayPicks、为你推荐=trending(week)，各取真实抓取首页 + `recommender.resolve` 库匹配（命中转 EmbyItem 进 Emby 详情，未命中留 SeerrMedia 进 Seerr 详情）；未配 TMDB/Seerr 时整行隐藏。删掉旧的 `_forYou` 本地查询与 seerr trending 独立行 |

## 4. 诚实边界

- 云端不连真实 TMDB/Seerr，"真实抓取内容是否正确、筛选面板是否好用、平台匹配是否命中"需真机配 key 验证。
- 流媒体平台靠 studio 名子串匹配，依赖刮削器把平台写进 Studios 字段；若某平台内容库里 studio 名不含约定关键词，会漏匹配（可后续加关键词）。
- 首页发现抓取行未配 TMDB/Seerr 时整行隐藏（不是显示空行），与纯本地 Emby 安装兼容。
- 发现页与首页发现行都是"点击进详情"，详情页内的播放/选集沿用现有 Emby/Seerr 详情逻辑，本次未改动播放本身。
