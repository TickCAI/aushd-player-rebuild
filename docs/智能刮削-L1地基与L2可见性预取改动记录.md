## 一、背景与目标

用户导入的媒体库常常缺失元数据（尤其挂载网盘、刚导入的库、非自建的 Emby/Jellyfin）。
此前只有 `MetadataLocalizer.fillMissing()`，它有两个硬限制：

1. **必须有 `tmdbId`** 才会补（`needsFill` 要求 `item.tmdbId != null`）；
2. **只在详情页打开时补**，列表里依然是光秃秃的标题 + 播放按钮。

用户要求：自动智能刮削应当「无感」——下滑时海报基本已加载好。

## 二、五条硬规则（与用户确认）

1. **零写回**：绝不动用户的上游媒体库（不调用 Emby/Jellyfin 任何写接口）。
2. **上游不可用时照样能看**：刮削结果只是渲染层覆盖，服务端挂了也照常显示已缓存的海报。
3. **可一键清除**：缓存全部在应用私有目录，`clearCache()` 一步撤销。
4. **缓存 key 要稳**：**永不使用上游 `item.id`**（换服务器/重新导入就变）。优先级：
   `tmdb:<id>` > `imdb:<id>` > `name:<规范化片名>:<年份>` > `path:<路径 FNV hash>`。
5. **宁缺毋滥**：缺一张封面用户能接受；封面张冠李戴用户会认为软件坏了。低置信一律留空。

## 三、L1 地基（commit `f9aa715`）

纯逻辑、零 I/O、零网络，共 4 个文件 488 行。

### `lib/data/scraper/filename_guess.dart`
`FilenameGuesser.guess(filename)` → `FileGuess(title, year, season, episode, isTv, confidence)`。

- 季集识别：`SxxEyy`、`NxM`、`第N季第N集`、`第N集`（仅集号时 `isTv = true`）。
- 年份：`(19|20)\d{2}`。
- 清洗画质/编码/音轨/版本标签：`2160p/1080p/4K/HDR/DV/WEB-DL/BluRay/x264/x265/HEVC/AAC/DTS/10bit/PROPER/REPACK/IMAX/DIRECTOR'S CUT` 等，以及 `[...]`、`(...)`。
- 置信度起点 0.45：标题≥2 字 +0.15、有年份 +0.20、判定剧集 +0.20、标题≥4 字 +0.05，上限 1.0。
- 纯数字名、空名返回 `null`（不猜）。

### `lib/data/scraper/match_score.dart`
`MatchScorer.score(...)` → `MatchScore(score, reason)`；`verdict(score, secondBest:)` → `MatchVerdict`。

- 打分：文本相似度 × 0.75，同年 +0.20 / 差 1 年 +0.06 / 不同年 −0.15，类型一致 +0.05 / 不一致 −0.10。
- 文本相似度 = token 集合 Dice 系数与包容度的均值（对词序和残留标签鲁棒）。
- 闸门：`≥ 0.78` → `auto`；`< 0.55` → `skip`；中间但领先第二名 `≥ 0.12` → `auto`；否则 `review`。
- `review` **永不自动应用**，只入缓存备将来「更正元数据」入口用。

### `lib/data/scraper/scraper_cache.dart`
- `ScraperCache.instance`（单例），落盘 `scraper_cache.json`（`getApplicationSupportDirectory`，原子写 tmp+rename）。
- TTL：命中 30 天、未命中 2 天（避免同一个解析不出名字的文件每次滚动都重查 TMDB）。
- 3 秒 debounce 批量写盘，`compute(jsonEncode)` 避免阻塞 UI isolate。
- `scraperCacheKey({tmdbId, imdbId, name, year, path})` 实现上面的 key 优先级。

### `test/smart_scraper_test.dart`
12 个用例：解析 4（电影/SxxEyy/中文季集/拒绝纯数字）、打分 4（精确 auto / 年份错误 skip / 明显领先 auto / 中间分 review）、缓存 key 3。

## 四、L2 可见性驱动预取（commit `d2ed0cd`、`536ccf0`）

### `lib/data/scraper/smart_scraper.dart`（新增，327 行）
`SmartScraper extends ChangeNotifier`：

- `scrape(EmbyItem)` → `ScrapeResult(item, applied, verdict, reason)`：
  1. 无 TMDB key → 直接 `skip`（返回原对象，`identical` 不变）；
  2. 已有 `tmdbId` → `skip`（交给既有 `MetadataLocalizer.fillMissing`，不重复劳动）；
  3. 类型不是 Movie/Series/Episode → `skip`；
  4. 从 `mediaSources[].path` 取 basename 喂 `FilenameGuesser`；猜不出且 `item.name` 也空 → `skip`；
  5. 查本地缓存 → 命中且 `apply == true` 才应用；命中 `review` 返回 `cached-review` **不应用**；
  6. 未命中且已有同 key 请求在飞 → 复用同一 Future（后台滚动不会重复打网络）；
  7. 否则 TMDB `searchMulti` 取前 5 候选 → 每个打分 → 排序 → 取 best/second → `verdict()`；
  8. `auto` 才 `copyWith(localizedPosterPath / overview)`；`review`、`skip` 都只写缓存不应用。
- 并发闸 `_Gate(3)`：行批量预取时最多 3 个在飞，避免打爆 TMDB 速率。
- `appliedCount / attemptedCount` 供 L3 进度 UI 使用。
- `prefetch(items)`：只挑真正缺封面又没 `tmdbId` 的项，异常全部吞掉，绝不打断滚动。

### `lib/app/app_services.dart`
- 新增懒加载 `SmartScraper? get scraper`：无 TMDB key 返回 `null`（全链路静默 no-op）；
  key 或语言变化时自动重建。
- `updateSettings` 的 `metadataChanged` 分支里 `_scraper = null` 强制重建。

### `lib/ui/pages/home_page.dart`
- `_load()` 成功、写入 `_resolved[row]` 后调用 `_scrapeRow(row, services, items)`——**不阻塞行加载**。
- `_scrapeRow`：只挑 `tmdbId == null && primaryImageTag 空 && localizedPosterPath == null` 的 `EmbyItem`；
  后台 `await scraper.ready` 后逐个 `scrape`；`applied` 时把 `_resolved[row]` 里**同一对象替换**为
  `result.item`，并把 `_data[row]` 换成已完成的 `Future.value(updated)` + `setState`，
  `FutureBuilder` 立刻拿到新数据重绘卡片。
- 未 `applied`（review/skip/error）时**完全不动**该行——不会出现错封面。

### `test/smart_scraper_service_test.dart`（新增，178 行）
8 个用例：无 key no-op（且返回原对象）、已有 tmdbId 不重刮、高置信应用海报+简介、
低置信不应用、（review 二次调用仍是 `cached-review` 不应用）、空结果记 miss 且不重复请求网络、
网络 500 不抛异常且不应用、`prefetch` 只挑真正需要的、`clearCache` 清空决策。

## 五、渲染链路为什么能生效

`lib/ui/core/artwork.dart` 的 `poster(item)` 在服务端无图时直接用 `item.localizedPosterPath`
走 `TmdbApi.imageUrl`；有服务端图时把它注册为 backup。因此刮削结果只需要写 `copyWith` 的
`localizedPosterPath`，卡片与详情页无需任何改动即可显示中文海报。

`details_page.dart` 的 `localize(item)` 与本次预取共用一个 `_TmdbCache` 语义，
但本次不复用 `_TmdbCache`（key 语义不同：那边按 tmdbId，这边按猜名结果），互不干扰。

## 六、诚实边界

- **云端 CI 不联网 TMDB**：只验证编译、静态分析、单测、构建。真实中文命中率需真机验证。
- 中文片名的模糊匹配上限受 TMDB 中文别名库限制；`review` 档目前**只缓存不展示**，
  「更正元数据」入口留待 L3。
- 文件名解析对「纯中文无年份无季集」的猜测置信度偏低，多数会落到 `review`/`skip` 留空——
  这是刻意的：宁可空着也不上错封面。
- 缓存位于应用私有目录（`scraper_cache.json`），不随媒体库迁移；换机需重新刮（可接受）。
- 未做后台全库扫描（用户已定：默认关，靠可见性预取撑无感，另给手动按钮）。

## 七、后续（L3 / L4）

- **L3**：设置页「补全媒体库」手动按钮 + 进度（用 `attemptedCount/appliedCount`）+「清除刮削缓存」
  （`SmartScraper.clearCache()` + `MetadataLocalizer.clearCache()`）+ 详情页「更正元数据」入口。
- **L4**（可选）：后端元数据聚合层，等 L1/L2 真机中文命中率数据再决定是否投入。

## 八、验证方式

真机（需配 TMDB key）：

1. 首页下滑 → 观察原本只有标题的卡片是否出现海报（后台预取生效）。
2. 断网重进 → 已刮过的仍显示海报（本地缓存生效）。
3. 设置页清缓存后重进 → 海报消失（可撤销）。
4. 全程观察 Emby 媒体库中该条目的图片/简介**未被修改**（零写回）。
